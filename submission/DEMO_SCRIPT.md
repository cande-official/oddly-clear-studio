# Oddly Clear Studio — three-minute demo

Actual product captures and real Meta outputs; processing waits shortened. Synthetic system narration.

## 0–16s

A technical explainer can look convincing and still teach the wrong thing. The hard part is connecting a claim to its source, and pointing at the exact moving part. Oddly Clear Studio brings those checks into one editor.

## 16–36s

Start with one clip, one readable PDF, and a question. This helicopter illustration was created during the hackathon. The reference is the FAA Helicopter Flying Handbook. This is an editing demonstration, not flight instruction. Your imported source stays attached to the project.

## 36–56s

Muse Spark reads the footage together with the extracted document pages. It drafts exactly four timed beats: a heading, a short explanation, a visible segmentation target, and a page-specific quotation. These are real API results. Processing waits in this demonstration are shortened.

## 56–76s

A quotation match is only the first check. Open the cited page and compare the actual claim. The editor keeps the wording editable. In this example, a direction-specific statement about yaw was generalized to match the supporting excerpt. Changing a claim removes its previous review.

## 76–96s

SAM three point one handles the geometry. A short concept prompt tracks the main rotor through the clip. The first tail-rotor request returned no object. Instead of pretending it worked, the editor preserved that failure. Drawing a box on a source frame gave SAM a concrete starting point.

## 96–115s

The seeded request returned eight hundred and forty frames of real tail-rotor masks. A repeated beat reuses that full-video result without another inference request. Object identity is preserved. A frame with no detection stays empty; an old mask is never silently carried across the gap.

## 115–135s

Review the source and the highlight separately for every beat. Edits to the explanation, timing, or selected object invalidate the matching review. Export remains blocked until the four-beat story is consistent. The public version separates browser sessions and reserves a fixed shared budget before calling Meta.

## 135–152s

Render produces a twenty-to-forty-second vertical film. The server decodes the entire output and checks its dimensions and frame count. This twenty-eight-second result contains eight hundred and forty frames. The actual browser download was also compared with the render using a file hash.

## 152–180s

Here is the finished silent cut, with the actual SAM highlights and source-page labels. The editor, source checks, tracking recovery, and renderer were built during this hackathon. Public code, the working studio, and this demonstration are linked together. Oddly Clear Studio: make the explanation clear, and keep its evidence visible.
